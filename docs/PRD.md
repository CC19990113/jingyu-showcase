# 鲸屿 · 产品需求文档（PRD）

> 版本：v1.0（首版范围）
> 适用项目：`dsh-community`（DeepSeek Harness 中文社区站）

本文档回答一个问题：**鲸屿首版要做成什么样，哪些行为已经被确定为「必须这样」，以及怎样判定它做完了。** 阅读对象是工程、设计、审核运营和后续接手的人；读完不需要再问需求方「这个功能要不要做」「审核卡在哪一步」。技术实现细节不在这里展开，见 [architecture.md](./architecture.md)、[database.md](./database.md)、[auth.md](./auth.md)、[api.md](./api.md)。

---

## 1. 产品定位

鲸屿是 DeepSeek Harness（DSH）的中文社区网站。形态由两块拼成：掘金式的**内容与专栏**承载长文，linux.do 式的**论坛与信任体系**承载提问、争论和日常交流。

它与普通技术论坛的差别只有一条，但这决定了几乎所有功能设计：

**帖子主体不是「一段经历」，而是「一份可粘贴的产物 + 一份可复现的实测记录」。**

作者发帖时可以直接附带：

- `patch` 片段（对 DSH 内核或配置文件的补丁）
- `yaml` 配置（provider、模型、工具权限）
- `json` 画布（AgentFlow 编排图）
- `bundle`（preset 打包结果）

同时标注本次实测的**环境条**：内核版本、平台、模型。读者看到的不只是「我这样配好了」，而是「在 DSH 0.9.3 + macOS arm64 + deepseek-v3.2 上，我这样配好了，这是原文件，点一下就能复制」。

差异化落在三个可验证的点上：

1. **产物体积优先**：帖子编辑器的入口不是「写点什么」，而是「贴一个能跑的东西」。
2. **环境可追溯**：每条实测记录带版本/平台/模型，评论区可以按环境复现问题。
3. **门槛受控**：邀请制 + 自动化审核 + 信任等级，让首版的信噪比在人力有限时仍然可控。

## 2. 用户角色

| 角色 | 判定条件 | 能做什么 | 不能做什么 |
| --- | --- | --- | --- |
| 访客 | 未登录 | 浏览公开帖子/评论、搜索、看用户主页 | 发帖、评论、点赞、举报、看 pending 内容 |
| 未激活账号 | 已用 GitHub/Google 登录，但没有有效的邀请兑换记录 | 浏览公开内容、看自己的账号状态、用邀请码补兑激活 | 发帖、评论、点赞、举报、生成邀请码 |
| Lv0 新人 | 已完成邀请兑换并建号，`trustLevel = 0` | 发帖（进审核队列）、评论（进审核队列）、点赞、举报自己可见的内容 | 免审发布、发邀请码 |
| Lv1 成员 | 至少 1 篇帖子被通过 | 正常发帖（仍走自动判定）、评论、点赞、举报、通知 | 发邀请码 |
| Lv2 可信成员 | 至少 1 个回答被采纳 | 发帖免审（敏感词命中仍进队列）、评论免审、正常互动 | 发邀请码 |
| Lv3 核心成员 | 至少 5 个回答被采纳且近 90 天无违规 | Lv2 全部能力 + 生成邀请码 | 使用管理后台 |
| Lv4 核心贡献者 | 人工授予 | Lv3 全部能力 + 免审与邀请码额度 | 使用管理后台（除非同时被授予 moderator/admin） |
| 审核员 | 管理员在后台授予 `role = moderator` | 审核、举报处理、禁言/封禁 | 授予 Lv4、管理敏感词/板块、修改审计日志 |
| 封禁用户 | `status = banned` | 无（登录被拒，已有 session 立即失效） | 一切写操作与登录 |

角色判定由三个字段共同决定：`User.role`（user / moderator / admin，权限面）、`User.trustLevel`（Lv0–Lv4，社区声望）、`User.status`（active / muted / banned，账号状态）。**激活状态不是字段**：存在任意一条 `InviteUse` 即视为已激活，`role = admin` 例外；未激活账号可以登录和浏览，但不能写。环境变量 `ADMIN_HANDLES` 中列出的 handle 在首次登录时被初始化为 `role = admin` 且 `trustLevel = 4`，用于引导第一个管理员、避免「没人能进后台」的鸡生蛋问题；这只是引导例外，不参与定时重算（重算任务跳过 Lv4）。除此之外，Lv4 与 moderator/admin 正交：Lv4 是声望等级，不一定能进后台；moderator/admin 是管理权限，`admin` 另行放行邀请码与管理能力。

## 3. 核心场景

**S1 装不上，来排障。**
用户在新机器上装 DSH，卡在 provider 鉴权。他在「排障」板块发帖，贴上错误日志和 `yaml` 配置片段，环境条填 `0.9.3 / linux-x64 / deepseek-v3.2`。另一位用户按环境条对齐版本，复制产物块本地复现，在评论区给出修正后的 `yaml`，作者点「采纳」。帖子自动标记已解决，进入「待解决 → 已解决」的信息流归档。

**S2 抄作业。**
用户看到一篇「抄作业」帖，正文几乎没有废话，只有一段 `bundle` 和一份 `patch`。他点复制，粘到本地，跑通。整个过程不需要读完正文，也不需要注册。

**S3 深读与讨论。**
「深读」板块承载对 DSH 架构、调度策略、工具权限模型的长文分析。文末的评论是楼中楼结构，允许引用式追问；作者可以采纳其中一条作为「官方补充」。

**S4 展示作品。**
「作品」板块发布基于 DSH 搭出来的东西：AgentFlow 画布 json、preset、CLI 工作流。帖子必须带至少一个产物块才允许发布（前端提示，不强制阻断，由审核员判断）。

**S5 踩坑实测。**
记录「我试了，结果是这样的」。环境条是强制阅读信息；同一条经验在 macOS 和 Linux 上可能结论相反，因此评论允许带自己的环境条回复（正文首行约定格式，见 6.2）。

**S6 新人被邀请进入。**
老用户生成邀请码 `https://jingyu.example/join/8F3K2Q`，发给朋友。朋友打开链接 → 页面预校验邀请有效 → 跳 GitHub 登录（请求带上邀请码）→ OAuth 回调的同一个事务里核销邀请、建号并激活 → 进入 Lv0。

如果邀请码在登录过程中失效（被别人用完、过期），账号仍然会建出来，但**未激活**：能看公开内容，不能发帖评论，页面回跳时带 `invite_error=INVITE_EXHAUSTED` 之类的错误码。朋友可以换一个新码，在 `/join/<code>` 或账号状态页走补兑路径激活，不需要重新注册。

**S7 审核员的一天。**
打开后台审核队列，先看帖子 tab，再看评论 tab。命中敏感词或 Lv0 新人的内容排在最前（按创建时间正序，先到先审）。通过、驳回（必填理由）、隐藏、删除四个动作都有二次确认；每一次动作写审计日志。举报队列单独一栏，处理完标记 resolved/dismissed。

## 5. 审核机制

### 5.1 自动判定顺序

发布（发帖、编辑触发重判、评论）时，服务端按以下顺序判定，**命中即停**，并把命中原因写入 `ModerationAction.reason`（例如 `rule:banned_word:pattern=api[_-]?key`）：

1. 正文或标题命中 `BannedWord`（`enabled = true`，`exact` 做包含匹配，`regex` 走编译缓存）→ `pending`
2. 作者 `trustLevel = 0` → `pending`
3. 作者近 30 天内被驳回（`ModerationAction.action = reject` 按目标作者聚合）≥ 2 次 → `pending`
4. 其余 → `approved`，直接公开

补充约束：

- 帖子与评论共用同一套判定顺序，但阈值独立配置（例如评论的驳回次数阈值可以更宽松）。配置键：`moderation.rules`，JSON 结构见 [database.md](./database.md) 的 `SiteSetting` 说明。
- 已 `approved` 的内容被编辑时，只重跑规则 1 与规则 3；Lv2+ 作者编辑不触发重判（避免正常修订反复进队列）。
- 管理员手动通过后，内容 24 小时内不再自动重判（避免与人工判断打架）。

### 5.2 状态机

只允许以下迁移，任何其它迁移一律返回 `400 INVALID_MODERATION_TRANSITION`：

```
                    ┌──────────────────────────────┐
                    │                              │
                    v                              │
   [pending] ──approve──> [approved] ──hide──> [hidden]
       │                       │
       └────reject───> [rejected] ──author edits──> [pending]
```

- `pending → approved | rejected`
- `approved → hidden`
- `rejected → pending`（作者修改后重提，重提时重新跑自动判定）
- `hidden` 是终态，只能由管理员再执行 `delete`；不提供 `hidden → approved` 的回滚（误隐藏的补救方式是删除后由作者重发，保证状态机只有四条边）
- `delete` 不改变 `moderationStatus`，而是物理删除对应行；删除前把内容摘要、作者、操作者写入 `ModerationAction` 与 `AuditLog`。被删除的行不再存在，外键级联清理产物、评论与点赞

### 5.3 可见性矩阵

| 内容状态 | 作者 | 其他登录用户 | 访客 | 管理员 |
| --- | --- | --- | --- | --- |
| pending | 可见，带「审核中」标 | 不可见 | 不可见 | 可见 |
| approved | 可见 | 可见 | 可见 | 可见 |
| rejected | 可见，附驳回理由，可重提 | 不可见 | 不可见 | 可见 |
| hidden | 不可见，收到通知 | 不可见 | 不可见 | 可见 |
| 已删除 | 列表/详情 404 | 404 | 404 | 内容已物理删除，仅审计日志可见摘要 |

作者在「我的帖子」里能看到自己 pending/rejected 的全部内容；搜索与信息流对所有用户一律过滤 `moderationStatus = approved`（管理员在后台审核队列里看 pending，不在公开信息流里看）。

### 5.4 编辑与重提

- 作者编辑 `rejected` 内容并保存后，状态自动回到 `pending` 并重新跑自动判定；不需要额外的「重新提交」按钮（编辑即重提，避免用户忘记点按钮而以为已提交）。
- 重提会清空上一次驳回理由的展示，但 `ModerationAction` 历史保留。
- 编辑 `approved` 内容若使其重新进入 `pending`，原内容立即从公开列表消失（不做「旧版本继续展示」）。

## 6. 关键交互约定

### 6.1 产物块

- 编辑器提供「添加产物」按钮，选择类型后出现名称（必填，默认按类型生成如 `patch-1`）、内容、备注三个字段。
- 内容框等宽字体、不自动换行折行（横向滚动）、不经过 Markdown 渲染。
- 详情页产物块显示类型徽标、名称、行数、复制按钮；复制内容为原始文本，不含前后标记。
- 产物块顺序可拖拽；排序值写入 `Artifact.sort`。
- 产物块只存文本，不存二进制、不存图片、不存链接预览。

### 6.2 环境条

- 发帖表单必填三项：`kernelVersion`（如 `0.9.3`，允许 `0.9.3-rc.1`）、`platform`（`darwin-arm64` / `linux-x64` / `win32-x64` 等）、`model`（自由文本，如 `deepseek-v3.2`）。
- 详情页环境条置顶，用等宽字体展示；信息流卡片只显示 `0.9.3 · darwin-arm64`。
- 评论区约定：需要补充环境时，首行写 `[env] 0.9.3 / linux-x64 / deepseek-v3.2`，前端解析为环境小标签。该约定由前端解析，不落库为结构化字段。

### 6.3 信息流与排序

- 「最新」按 `lastActivityAt desc` 排序（新帖/新回复都会上浮），置顶由管理员通过 `SiteSetting.featured` 配置。
- 「最热」窗口 7 天，公式 `likeCount * 3 + replyCount * 2 + min(viewCount, 10000) * 0.1`，结果缓存 60 秒。
- 「待解决」只在排障/抄作业/踩坑实测三个板块生效，按 `createdAt desc`，超过 30 天未解决的帖子降权显示。

### 6.4 审核中的内容

作者看到自己的 pending 帖子时，页面顶部固定一条提示条：「审核中，通常 24 小时内处理」。pending 内容不支持点赞、不支持被他人评论（作者自己的评论也进队列，但显示为审核中）。

## 7. 验收标准

以下 12 条按顺序点通即视为首版功能验收通过。每条都可由非开发人员手动执行；预期结果唯一。

1. **邀请码激活（主路径）**
   管理员生成邀请码 → 用无痕窗口打开 `/join/<code>` → 页面显示邀请有效 → 点 GitHub 登录并授权 → 回到站点后已登录且 `activated = true`，`usedCount` 增加 1、`InviteUse` 多一行、账号为 Lv0。
2. **无邀请码：能登录但不激活**
   无痕窗口直接访问 `/login` 并完成 GitHub 授权 → 回调正常建号并登录，但 `/auth/me` 返回 `activated: false`，页面回跳带 `invite_error=INVITE_REQUIRED` 并提示补兑；此时发帖/评论/点赞/举报均返回 403 `INVITE_REQUIRED`，`User` 与 `OAuthAccount` 各多一行，`InviteUse` 没有新行。
3. **邀请码用尽/过期**
   将邀请码 `usedCount` 改为等于 `maxUses` 后访问 `/join/<code>` → 页面提示「邀请码已用完」；若仍继续登录，账号建出来但未激活，回跳带 `invite_error=INVITE_EXHAUSTED`。换个有效码在 `/join/<code>` 补兑后即可发帖。
4. **两种登录方式**
   GitHub 与 Google 分别可完成登录并进入个人主页；同一自然人的两种登录方式得到两个独立账号（不做自动合并），两个 handle 不同且都能正常发帖。
5. **封禁即时生效**
   管理员封禁用户 A → A 在另一个浏览器刷新任意需要登录的页面，立即被登出并无法再登录；公开帖子仍可匿名浏览，但 A 的任何写操作返回 401。
6. **Lv0 发帖进审核**
   新建 Lv0 账号发帖 → 提交后跳转详情页，顶部显示「审核中」，帖子不出现在「最新」信息流；管理员账号能看到并点击「通过」后，帖子出现在「最新」信息流首屏。
7. **敏感词命中**
   在后台敏感词库添加 `exact` 词 `foobar-bad` → 用 Lv3 账号发一篇正文含该词的帖子 → 帖子进入 pending，后台队列显示命中原因 `banned_word`。
8. **驳回与重提**
   管理员对 pending 帖子点「驳回」不填理由 → 提交被阻止；填理由提交后，作者在「我的帖子」看到驳回理由；作者编辑并保存后，帖子自动回到 pending。
9. **产物块复制**
   发帖时添加一个 `yaml` 产物块，内容为 3 行配置 → 详情页点复制 → 剪贴板内容与原文逐字节一致（含缩进、不含行号）。
10. **环境条与评论**
    发帖时填写 `0.9.3 / darwin-arm64 / deepseek-v3.2` → 详情页置顶显示三项；另一账号发表评论、作者回复该评论（楼中楼）→ 回复展示在根评论下并展示 `@` 被回复人。
11. **采纳答案**
    作者点击某条评论的「采纳」→ 该评论出现采纳标、帖子显示「已解决」、被采纳者收到站内通知；对同一条评论重复采纳 → 返回 `ALREADY_ACCEPTED`；改采纳另一条评论 → 原采纳被替换，最终仅一条 `isAccepted = true`。
12. **审核与管理闭环**
    用户举报一条评论 → 后台举报队列出现该记录 → 管理员处理举报（隐藏该评论，状态变为 resolved）并禁言被举报用户 1 天 → 被禁言用户发帖返回「已被禁言」提示；审计日志中可按操作者查到「隐藏评论」与「禁言」两条记录。

补充（不作为第 13 条，随上述步骤顺带验证）：用标题中的中文词能搜到帖子；用正文中的英文标识符（如 `additionalProperties`）能搜到；用作者 handle 能搜到。ed25519 徽章链路在 `tools/dsh-verify.mjs` 可用后按 [auth.md](./auth.md) 第 3 节自测。

## 8. 明确不做（首版）

以下内容不在首版范围内。它们不是「以后一定做」，而是「现在明确不做」，避免评审时被反复提出：

- **邮件**：不发验证邮件、不发通知邮件、不做邮件找回。账号找回依赖 OAuth provider 本身。
- **图片上传**：不支持任何图片、附件、头像上传。头像走 OAuth provider 的 URL；产物块只存文本。
- **实时聊天 / 私信**：评论区是唯一的交流通道。
- **移动端 App / 移动端专属布局**：只做响应式 Web，最低支持 375px 宽度可读。
- **多语言**：界面与文档仅简体中文。
- **AI 反垃圾 / 语义审核**：只用敏感词 + 等级 + 历史驳回次数三条规则。
- **全文中文分词**：首版用 PostgreSQL `pg_trgm` + `simple` 配置，命中率不足时再引入 `zhparser`（见 [database.md](./database.md)）。
- **收藏夹、草稿箱**：原型侧栏留有入口，但首版不实现收藏与草稿持久化；草稿仅存浏览器 localStorage（实现与否不影响验收）。
- **全文导出、RSS、开放 API**：不提供。
- **多租户 / 多站点**：单站点单部署。

## 9. 术语

| 术语 | 含义 |
| --- | --- |
| DSH | DeepSeek Harness，本项目服务的开源 Agent 运行框架 |
| 产物块（Artifact） | 帖子附带的文本片段，类型为 patch/yaml/json/bundle，可一键复制 |
| 环境条（Env bar） | 帖子的内核版本 / 平台 / 模型三元组 |
| 信任等级 | Lv0–Lv4，决定是否免审、能否发邀请码 |
| 自动判定 | 发布时按敏感词、等级、驳回历史决定是否进审核队列 |
| pending / approved / rejected / hidden | 内容审核状态，见 5.2 |
| 徽章 | 「已验证 DSH 用户」，由 ed25519 设备签名派生 |
| SiteSetting | 站点级 JSON 配置表，承载审核阈值、置顶、敏感词开关等 |
